# Live catalog and programme data

Source contract: [iptv-org API](https://github.com/iptv-org/api) and [EPG guide publication](https://github.com/iptv-org/epg/blob/master/GUIDES.md). No catalogue entries or programme data are generated by this application.

`src/catalog.ts` loads all 13 documented public API datasets from `https://iptv-org.github.io/api/`:

| Endpoint | Used for |
| --- | --- |
| channels | Channel identity, name, country, category IDs, network, website, adult exclusion |
| streams | Playback/recording sources, feed matching, quality and availability labels |
| feeds | Active feed, languages, broadcast areas and broadcast timezones |
| logos | Current broadcaster logo variants and alternate URLs |
| guides | Channel/feed-specific XMLTV source discovery |
| categories | Published category names and descriptions |
| languages | Feed language codes resolved to names |
| countries | Country names/flags and country broadcast-area labels |
| subdivisions | Subdivision broadcast-area and city hierarchy labels |
| cities | City broadcast-area labels |
| regions | Regional broadcast-area labels |
| timezones | Validate and expose feed IANA timezone IDs |
| blocklist | Exclude upstream blocked channels; loading this endpoint is required before catalog publication |

A failed optional endpoint is exposed through `endpointStatus`; unavailable metadata stays empty. Required channels, streams, and blocklist failures show a catalog error. Only HTTPS stream/image/guide sources are requested by the browser, to support secure GitHub Pages hosting.

`src/programmes.ts` lazily loads the XMLTV URLs published in guides.json. It caches at most 16 documents for five minutes, limits concurrent document requests to four, and bounds compressed and decoded guide data to 12 MB. Current and next entries require a real publisher title and valid start and stop times. Guide images come only from programme `icon` or `image` metadata. No current programme, thumbnail, duration, or upcoming show is inferred from a channel logo/category/stream title. UTC offsets in XMLTV are honored; timestamps without offsets follow XMLTV's UTC convention. Explicit channel/feed IDs are preferred; display-name matching is permitted only when the name maps to one guide channel.

The upstream EPG project is a generator/discovery project, not a guaranteed centrally hosted schedule API. Sources may be missing, expired, offline, CORS-blocked or too large for this browser. These are surfaced as unavailable/empty guide states. A guide cannot guarantee that every listed programme is being transmitted by the chosen stream.

The local files under `tests/` contain synthetic test fixtures only. They are available only through explicit development test routes, which return 404 in production. Synthetic media is never used by the runtime catalog.

XMLTV timestamp and image semantics follow the [XMLTV DTD](https://github.com/XMLTV/xmltv/blob/master/xmltv.dtd). External DTD declarations are stripped; internal entity declarations are rejected.

Live check on 2026-10-26: guides.json returned 180,678 records; zero records contained published source URLs. Programme UI consequently reports unavailable data. This is an observed upstream condition, not an application test fixture.

## Live thumbnail fallback
When programme art is missing or fails, visible cards capture a frame from one of the channel’s first two real stream URLs. At most three capture pipelines run at once, each with a 10-second limit. Streams are disconnected after the frame is captured. A five-minute cache (at most 100 JPEGs) avoids repeated work on navigation. Snapshots are labelled with capture time and do not claim programme identity. CORS-restricted, offline or unsupported streams still show an unavailable state. No external proxy or fabricated image is used.

### Recording compatibility

HLS recording now uses a same-origin, catalog-authorized Next.js proxy to collect
unencrypted TS/fMP4 segments, including initialization ranges and default separate
audio. It selects a fixed rendition at or below 720p when available, caps combined
source data at 128 MiB, and remuxes in a single-thread FFmpeg WASM worker without
re-encoding. Output is MP4 where compatible or Matroska otherwise. Discontinuities
become separate parts. Finalization failures retain source data for retry; cancel
releases the worker and collected data.

Browser capture remains an explicit fallback: native video capture where available,
or canvas (up to 1280×720 at 24 fps) plus Web Audio. No camera or microphone is used.
Keep the tab visible and device awake, including for scheduled starts. Source
restrictions, unsupported encryption/codecs, autoplay rules, mobile suspension and
browser memory limits still apply. Proxy access cannot bypass DRM or upstream
authentication. Safari/iPhone behavior is not certified by Chromium tests.

The development-only `/test/recording?fallback` fixture checks the capture fallback;
`/test/wasm` plus `tests/recording-e2e.mjs` checks actual generated video/audio through
the WASM engine. Native ffmpeg/ffprobe are used only to generate and verify test media.
